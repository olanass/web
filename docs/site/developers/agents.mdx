Agents use Olanas to find API projects and buy access to useful operations. The remote MCP server exposes catalog and order tools. Payment signing stays in the owner's wallet or the separate local wallet companion.

## Choose a payment workflow

| Workflow | Who authorizes and signs? | How results are recovered |
| --- | --- | --- |
| Website order | A human reviews the private approval link and uses a browser wallet. | Read the original durable order. |
| Local companion | An owner-enabled local signer acts within its spending-session policy. | Use the companion's original request ID and order journal. |
| Direct gateway | Your integration manages its own authorized signer and payment proof. | Follow direct-gateway receipt rules; it is not the saved-order API. |

## Connect to the remote MCP server

Use a client that supports Streamable HTTP and configure the URL `https://olanas.xyz/mcp`. This is a tool endpoint, not a browser page.

```json
{
  "mcpServers": {
    "olanas": {
      "url": "https://olanas.xyz/mcp"
    }
  }
}
```

Client configuration formats can differ. The remote endpoint does not create a wallet, hold a private key, or authorize spending.

## Discover and inspect

Use `search_apis` with a query or category. Use `get_api_details` for the selected slug to inspect its allowed methods, input schema, gateway URL, and optional OpenAPI document.

Construct the operation from the published contract. Do not invent required fields or assume every API accepts the same JSON body.

## Prepare a human-approved order

1. Call `new_order_identity` once. Save its `requestId` and private `accessToken`.
2. Call `create_order` with those identifiers, the selected `slug`, allowed `method`, optional relative `path`, and JSON `body`.
3. Save the returned order ID and show its private `approvalUrl` to the owner.
4. Wait for the owner to review the request and quote, sign approval, and confirm the transfer.
5. Call `get_order` with the original order ID and access token to retrieve status and results.
6. If the original payment is submitted but pending, use `reconcile_order`. It verifies that transfer and finishes eligible processing without creating a new payment.

Retry interrupted creation with the same request ID and access token. A fresh identity represents a new purchase.

The saved result contains an HTTP status, content type, and base64 response body. Decode the body according to its content type and treat it as untrusted service output.

## Remote tool reference

| Tool | Purpose |
| --- | --- |
| `search_apis` | Search live API listings. |
| `get_api_details` | Inspect metadata, input schema, and optional OpenAPI. |
| `new_order_identity` | Generate credentials for one intended purchase; does not create or pay an order. |
| `create_order` | Prepare a request and quote for approval; does not execute it. |
| `get_order` | Read private order status and saved results. |
| `reconcile_order` | Check the original submitted payment and finish eligible delivery. |
| `get_payment_requirements` | Read the direct gateway's canonical payment requirement. |
| `check_wallet_balance` | Read a public address's configured-asset balance. |
| `call_paid_api` | Call a gateway with an optional public payment proof; without proof, receive the 402 challenge. |
| `get_payment_receipt` | Retrieve a direct-gateway settlement receipt by ID. |

## Local wallet companion

The [Pay & run setup guide](https://olanas.xyz/payments#agent-wallet-guide) provides installation commands and owner controls. The companion is distributed from the `olanas-payments-mcp` branch of `olanass/web`, separately from the website's main branch.

Install Node.js 22 or newer, Git, and your chosen local AI client. Example installation commands:

```sh
# Codex
npx --yes github:olanass/olanas-payments-mcp install --client codex --auto-config --network mainnet --launchpad https://olanas.xyz

# Claude Desktop
npx --yes github:olanass/olanas-payments-mcp install --client claude --auto-config --network mainnet --launchpad https://olanas.xyz

# Claude Code
npx --yes github:olanass/olanas-payments-mcp install --client claude-code --auto-config --network mainnet --launchpad https://olanas.xyz
```

The installer creates or reuses its own encrypted local wallet. It does not import a browser wallet or enable spending automatically. Use the installer output for manual client registration if automatic setup is unavailable.

The owner opens the private local wallet link, funds the dedicated wallet with the selected payment asset and ETH for gas, and enables a session with amount, gas, time, service, and recipient limits. Those are local application policies, not smart-contract limits. Restarting the companion disables new autonomous signing.

The companion exposes `search_services`, `request_paid_api`, `get_payment_status`, and `reconcile_order`. These are local tools; do not confuse them with the remote tool names above.

Confirm that the installed companion version supports the website's durable-order flow before enabling a spending session. The website and companion have separate release lifecycles.

## Recovery and boundaries

Keep approval URLs, order access tokens, local wallet links, and owner credentials private. Never put a private key, seed phrase, or owner password in an agent prompt.

Stop on `needs_owner_action`, a rejected order, or unknown delivery. Do not create a replacement purchase automatically. A saved API error does not mean the original payment failed.
